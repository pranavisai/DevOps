## IAM Users
1. An IAM user can access AWS using the management console, CLI, or SDKs.
2. The configuration takes place under AWS IAM (Identity and Access Management).
3. To access any service, users need to be given permissions through policies, either as groups or roles.
4. ``` aws sts get-caller-identity ``` -> to see which identity is currently being used within the CLI.
5. ```aws configure --profile <iam-user> ``` -> to switch to a new user within CLI.
6. To get the Access key and secret access key
   ``` Go to IAM User profile -> Security Credentials -> Create access key -> CLI ```

## IAM Groups
1. Used to simplify user management.
2. Best rules for IAM groups:
   1. Provide descriptive names
   2. Similar roles in the same group
   3. Assign policies so that the users within a specific group will have similar permissions.

## IAM Policies and Permissions
1. Implement the Principle of Least Privilege
2. IAM permissions provide fine-grained control over the actions performed on AWS resources.
3. A collection of permissions are policies.
4. IAM policies have Effect, Actions, Resources, Conditions, and Principal (Entity that the policy applies to) 

## CloudTrail and User Access Audit
1. Logs APi calls to AWS services, for example, stopping an EC2 instance
2. Audit actions taken by users, services, and AWS resources
3. Track and review API calls made by AWS IAM users, for example, accessing an S3 bucket.
4. Detect successful and unsuccessful login attempts and detect security threats.

## Identity policies
1. Types:
   1. AWS Managed policies: Quick and easy to use but may not cover all use cases. They allow us to define policies once and apply them to multiple entities, making it easier to manage and update policies at scale.
   2. Customer-managed policies: More customizable and can be reused but require more management, which adds overhead.
   3. Inline policies. Attach directly to an entity but can't be reused.
2. Inline policies are created and attached directly to an IAM entity.

## MFA ( Multi-factor authentication )
1. MFA is a feature that adds an additional layer of protection for IAM users.
2. Configure MFA with a hardware token or a virtual app (like an authenticator).
3. Users use a username and password for the first factor and a one-time password from the MFA as the second factor.
4. MFA enhances security by adding an extra layer of security for authentication.

## Password Policies
1. Password policies are account-level policies that apply to all users in the AWS account.
2. AWS IAM applies default password policies for all users in the AWS account.
3. We can configure custom policies based on our governance requirements in the workplace.
4. Configure password length, complexity, expiration, and password reuse policies.

## Security Token Service (STS)
1. It is a web service that can provide temporary credentials.
2. If an IAM user, IAM role, or an AWS service needs temporary access to AWS resources, they will send a request to the STS service, which will provide temporary keys that are generated by it for access.

## Share resources with RAM
1. AWS Resource Access Manager: Shares resources across AWS accounts or AWS organizations by creating a resource share.
2. Select resources: Select the resources that you would like to add to a resource share.
3. Specify principals: Specify accounts or organizations that can access the resources in the resource share.
4. Share resources: The specified principals will now have access to resources in the Resource share.

## Identity Federation
1. Identity federation links a user's digital identity across separate systems or organizations. It lets a user log in once at an Identity Provider to access different apps or websites without making a new password for each one.
2. AWS has various options like
   1. SAML 2.0 response for LDAP database authentication.
   2. OpenID Connect if the user wants to authenticate outside AWS.
   3. OAuth 2.0, as it is an industry standard.
3. Benefits of Identity Federation in AWS:
   1. Simplifies user management
   2. Centralized authentication
   3. Improved security
   4. Reduces risks.
  
## AWS Private Link
1. It allows users to securely access AWS services without exposing traffic to the internet.
